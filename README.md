# RoutineEscape

RoutineEscape — учебный Telegram-бот на C#/.NET для личных задач, событий, напоминаний и заметок. Проект помогает на практике изучить backend-разработку: обработку сообщений, архитектуру приложения, работу с базой данных, фоновые процессы, проверки доступа и автоматизированное тестирование.

**Бот в Telegram: [@RoutineEscape_bot](https://t.me/RoutineEscape_bot).** Он запущен локально через **long polling** и доступен, пока работает компьютер и процесс приложения. Постоянный облачный хостинг пока не настроен.

Распознавание сообщений работает на локальных правилах и регулярных выражениях. **AI/LLM в рабочем сценарии не используется**, ключи AI не нужны. Исходный текст сохраняется без перефразирования; дата и время извлекаются отдельно.

План развития — [техническое задание](RoutineEscape_TZ_v0.1.md), история последних изменений — [CHANGELOG](CHANGELOG.md).

## Возможности бота

| Возможность | Как работает |
| --- | --- |
| Создание записей | Отправьте обычный или пересланный текст. Бот предложит тип по правилам либо попросит выбрать его вручную. Запись создаётся после подтверждения. |
| Задачи | Название, срок с датой или точным временем; выполнение, восстановление, изменение и удаление с подтверждением. |
| События | Дата и время, уведомления, изменение названия и перенос с сохранением длительности, если она задана. |
| Напоминания | Точный срок или относительный интервал; уведомление, подтверждение и перенос. |
| Заметки | Сохранение, просмотр, изменение полного текста и удаление с подтверждением. |
| Списки и меню | Сегодня, ближайшие семь дней, просроченные, выполненные и разделы по типам. Пагинация по пять записей и открытие карточки из списка. |
| Поиск | Буквальная подстрока без учёта регистра по своим записям, включая историю; полное содержимое заметки также участвует в поиске. |

| Несколько пользователей | Общая база данных с привязкой записей к владельцу и проверками доступа при каждом действии. |
| Компактный интерфейс | После успешного ответа на кнопку удаляется прежнее сообщение бота в личном чате. В списках названия и просрочка выделены жирным, даты — курсивом. |

Уведомления получают активные напоминания, события и задачи с явно указанным временем. Если уведомление не подтверждено и не отложено, отправляется один повтор через 10 минут. Кнопки позволяют нажать «Готово», отложить на 10 минут или на час. Это повтор доставки одного уведомления; периодические задачи «каждый день» пока не реализованы.

## Пользователи и хранение данных

Бот поддерживает несколько пользователей в одной базе PostgreSQL. Отдельная база для каждого человека не создаётся: записи разделяются по владельцу.

1. Из входящего Telegram-сообщения или нажатия кнопки берётся ID отправителя — `From.Id`.
2. По нему приложение находит `AppUser.TelegramUserId`. При создании первого Draft отсутствующий пользователь добавляется в базу. Уникальный индекс на Telegram ID предотвращает появление двух строк с одним идентификатором.
3. У пользователя есть внутренний `AppUser.Id` типа GUID. Именно на него ссылается `UserId` задач, событий, напоминаний, заметок и черновиков.
4. Списки и поиск загружают записи только найденного владельца. При открытии, изменении, выполнении и удалении конкретной записи приложение дополнительно сверяет её `UserId` с текущим пользователем. Одного знания ID чужой записи недостаточно для доступа через бота.

```text
Telegram From.Id
    → AppUser.TelegramUserId
    → AppUser.Id
        → TaskItem.UserId
        → CalendarEvent.UserId
        → Reminder.UserId
        → Note.UserId
        → Draft.UserId
```

Например, у Анны и Бориса могут быть задачи с одинаковым названием «купить молоко»: это разные записи с разными владельцами. Поиск Анны не возвращает задачу Бориса. Имя и `@username` не используются как ключ доступа; изменение ника не меняет привязку записей к Telegram ID. Для пересланного сообщения владельцем создаваемой записи становится пользователь, который отправил его боту, а сведения об исходном авторе хранятся отдельно как источник.

Часовой пояс и язык также хранятся в профиле пользователя. Моменты времени записей хранятся в UTC, а даты для ввода и отображения обрабатываются в его часовом поясе. Пользователи, записи и очередь уведомлений сохраняются в PostgreSQL и переживают перезапуск приложения.

Проверки доступа выполняются на уровне приложения; это не отдельные базы и не изоляция от администратора PostgreSQL. Тесты проверяют чужие ID, списки и поиск другого пользователя, изменения и удаление, а также владельцев кнопок. При переносе бота на сервер необходимо перенести существующую базу, если требуется сохранить записи: запуск с пустой базой не восстановит их автоматически из Telegram.

## Как бот запущен сейчас

Для локальной разработки используется long polling: приложение само получает обновления у Telegram. Бот работает отдельным фоновым процессом на компьютере; остановка процесса или выключение компьютера останавливает приём сообщений и своевременную доставку уведомлений.

Исходный план ТЗ предусматривает webhook и развёртывание приложения через Docker. Webhook endpoint уже есть, но текущий локальный запуск его не использует. Docker-конфигурация самого приложения пока не завершена. Long polling также можно использовать на сервере; переход на webhook нужен не для самого факта переноса, а для другого способа получения обновлений. Для существующего планировщика необходим постоянно работающий процесс и постоянное хранилище данных.

### Ограничения готовности MVP

- Нет редактирования полей существующего Draft. Выбор альтернативного типа подтверждает сохранение этим действием. Для исправления даты нужно отправить сообщение заново.
- Часовой пояс хранится и учитывается; `/timezone` показывает текущую зону/смещение и позволяет изменить её. Новые пользователи получают `Asia/Almaty` по умолчанию; перед первым уведомлением проверьте системное смещение через `/timezone`.
- Event и Reminder без даты/времени, с неверной, прошедшей или неоднозначной датой не сохраняются: бот просит повторить сообщение с уточнением. Редактирование уже сохранённой записи работает; редактирование Draft и часть форматов раздела 12 ТЗ ещё не реализованы.
- Основные незакрытые критерии раздела 32 ТЗ: редактирование Draft, запуск приложения через Docker и CI. Наличие методов Domain или общего репозитория не означает готовность пользовательского сценария.

## Локальная PostgreSQL

Для отдельной учебной БД можно использовать Compose. В текущем файле PostgreSQL опубликована на порту **5433** компьютера; локальная установленная PostgreSQL может работать отдельно на 5432. Пример ниже использует демонстрационные реквизиты из Compose, не предназначенные для публичного сервера:

```powershell
docker compose up -d postgres
$env:ROUTINEESCAPE_CONNECTION_STRING = "Host=localhost;Port=5433;Database=routineescape;Username=routineescape;Password=routineescape_dev"
dotnet ef database update --project RoutineEscape.Infrastructure
dotnet user-secrets set "ConnectionStrings:RoutineEscape" "$env:ROUTINEESCAPE_CONNECTION_STRING" --project RoutineEscape.Bot
```

Если команда `dotnet ef` не установлена, установите инструмент: `dotnet tool install --global dotnet-ef --version 10.0.4`. Строка подключения для design-time команд читается из `ROUTINEESCAPE_CONNECTION_STRING`; без переменной factory использует localhost:5432. Запущенный бот предпочитает `ConnectionStrings:RoutineEscape` из конфигурации/User Secrets, затем переменную окружения. При уже установленной PostgreSQL укажите её фактические реквизиты вместо запуска второй базы. `.env.example` служит образцом; текущий Compose содержит значения непосредственно в YAML и не подставляет их из `.env`.

PostgreSQL-тесты запускаются только на отдельной базе `routineescape_test*` либо одной изолированной схеме `routineescape_*test/audit*`; использовать строку рабочего бота нельзя. Тесты проверяют это перед миграцией:

```powershell
$env:ROUTINEESCAPE_TEST_CONNECTION_STRING = "<строка отдельной тестовой базы или схемы>"
dotnet test RoutineEscape.IntegrationTests
```

Без этой переменной PostgreSQL-тесты явно помечаются как пропущенные; остальные тесты используют изолированное in-memory хранилище.

## Telegram

Для локальной разработки достаточно задать токен и запустить приложение. В окружении `Development` бот автоматически удаляет зарегистрированный webhook и получает updates через long polling:

```powershell
dotnet user-secrets set "Telegram:BotToken" "<bot-token>" --project RoutineEscape.Bot
dotnet run --project RoutineEscape.Bot
```

HTTPS tunnel и регистрация webhook для локального запуска не нужны. `/start` возвращает приветствие, а обычный текст открывает предложение Draft по правилам или выбор типа при неоднозначности.

Распознавание работает локально, без AI-ключей и обращений к LLM. Примеры:

- «созвон завтра в 19:00» или «созвон завтра в девятнадцать ноль ноль» → событие;
- «купить молоко» → задача;
- «напомни через 40 минут выключить духовку» → напоминание;
- «номер аудитории — 305» → заметка;
- «завтра универ» → ручное уточнение типа.

Бот показывает предложение, а сущность сохраняется после нажатия кнопки. Текущие правила используют словарь признаков, сохраняют исходный текст как название и не извлекают место автоматически. Словесное время поддерживается для формы «в <час> ноль ноль» (0–23); произвольные словесные минуты, даты вида 12.09 и «в следующую пятницу» пока требуют повторной отправки в поддерживаемом формате. «Утром», «днём», «вечером» означают 09:00, 14:00 и 19:00 соответственно. Для событий/напоминаний без относительного интервала требуется явно указанная дата и время. Расчёт использует TimeZone пользователя из БД и системные данные часовых поясов.

Существующий AI-код сохранён вне актуального плана. Его настройка не требуется: штатно зарегистрирован RuleBasedMessageInterpreter. HTTP-логи уровня Information отключены, чтобы URL Telegram с токеном не попадали в стандартный вывод.
Для будущего production-режима задайте `Telegram__UseLongPolling=false` и `Telegram__WebhookSecret`. Webhook принимает `POST /api/telegram/webhook` и проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`. Токен и webhook secret не должны храниться в `appsettings.json` или Git.

Секреты нельзя добавлять в Git. Значения в `.env.example` предназначены только для локальной разработки; реальные пароли и будущие токены передаются через переменные окружения или secret store.

## Локальные логи

Журнал одновременно записывается в консоль и в `RoutineEscape.Bot/logs/routineescape-YYYY-MM-DD.jsonl` при стандартном запуске из README. Путь считается от content root приложения; каталог `logs/` исключён из Git. Каждая строка — JSON-запись, новый файл начинается с новым днём UTC. Хранятся текущий день и предыдущие 6 дней. Старые дневные файлы удаляются при старте, перед записью и ежечасно, даже если сообщений нет. Посторонние файлы не удаляются.

По согласованию пользователя локально сохраняются входящий текст, распознанный тип, подготовленный ответ и названия кнопок. `UpdateId` и уникальный `ProcessingId` в scopes связывают всю обработку, включая `/start` и callback. `Telegram accepted response` означает успешный ответ API (для сообщения записывается его Telegram message ID), а не прочтение пользователем. `Telegram response failed` содержит тип исключения и числовой код API, когда он есть. Также фиксируются завершение обработки и её длительность.

Все подключённые провайдеры заменены единым провайдером с очисткой перед консолью и файлом: маскируются значения секретов из конфигурации, пароли connection string, Telegram-токены/URL и распознаваемые записи паролей и API-ключей в тексте. Тексты, данные и stack trace исключений не записываются; остаются только типы исключений. Категории System.Net.Http полностью подавлены, в том числе при ошибках. Файлы не отправляются внешним сервисам.

При запуске `Telegram polling ready` подтверждает снятие webhook и переход к получению updates. Для проверки ответа ищите полную цепочку от `Update received` до `Telegram accepted response` с одним ProcessingId; один `/health` не подтверждает работу polling. При недоступности файла запись в консоль продолжается с безопасным сообщением о сбое записи.
## Обзор после сохранения

После подтверждения бот отправляет название, тип и дату сохранённой записи, затем до пяти других пунктов: на сегодня и следующие два календарных дня по часовому поясу пользователя, плюс свежие заметки и задачи без срока. Для записей без даты резервируются до двух мест; свободные места заполняются остальными подходящими пунктами. Датированные записи идут по времени, без даты — от новых к старым. Сохранённая запись не повторяется в сводке, даже если относится к ближайшим дням; дальняя дата также видна в подтверждении. Длинные заголовки сокращаются до 80 символов, пустые секции не выводятся.

Кнопка «Показать всё» открывает актуальные записи текущего пользователя по пять пунктов со стрелками «Назад»/«Далее» и номером страницы. Включены незавершённые задачи, активные напоминания, события сегодняшнего дня и будущие/продолжающиеся события, все заметки. Завершённые и отменённые задачи, сработавшие/отменённые напоминания, завершившиеся до сегодня события не показываются. Просроченные активные записи доступны в полном списке с отметкой. Сводка указывает, сколько дополнительных записей доступно там. Список пересчитывается при каждом нажатии; при изменении данных состав страниц может измениться.

Фильтр владельца применяется при запросе в БД; ответ отправляется в личный чат нажавшего пользователя, даже если callback пришёл из другого чата. Чужой ID не передаётся в кнопках. Для текущего MVP сервис загружает актуальные записи только этого пользователя и формирует страницы в памяти; для больших персональных архивов потребуется перенести общую сортировку и пагинацию в БД.
## Управление записями

В сводке и полном списке нажмите «Открыть: …» (для новой записи — «Открыть сохранённую запись»). Карточка показывает текст, тип, дату, часовой пояс и статус. У задачи доступны «Выполнено» и «Вернуть в задачи»; выполненная задача исчезает из актуального списка, но карточка позволяет восстановить её.

У всех четырёх типов можно изменить название/текст и удалить запись. У задачи меняется срок, у события и активного напоминания — дата и время. Нажмите поле, затем отправьте новое значение одним сообщением: название до 500 символов, текст заметки до 3500. Текст заметки заменяет содержимое и снимает старое отдельное название; теги сохраняются. Для даты используйте «завтра в 19:00», «12 сентября в 15:00» или «через 40 минут»; у задачи можно указать только дату, а «-» убирает срок. Часовой пояс берётся из пользователя; неопределённая/неверная дата не меняет запись. Перенос события сохраняет его длительность, если она была задана.

Кнопка «Отмена» или `/cancel` завершают режим без изменений. В режиме редактирования текст не запускает создание нового Draft; неверный ввод можно повторить. Режим действует 15 минут. После изменения возвращается свежая карточка, после удаления — актуальный список. Удаление происходит только по отдельной кнопке «Да, удалить»; простое открытие подтверждения ничего не удаляет.

Все действия и состояния проверяют владельца. Новая карточка выдаёт новые токены действий; старые кнопки, повторное удаление и действия над удалённой/изменённой записью безопасно отклоняются. Кнопки открытия остаются пригодны для получения свежей карточки. Состояния редактирования и токены карточек сохраняются атомарно в `RoutineEscape.Bot/state/record-interactions.json` (метаданные без текста сообщений), чтобы переживать перезапуск; каталог исключён из Git. Эта реализация рассчитана на один локальный экземпляр бота. При повреждении файла запуск прекращается, вместо незаметной потери режима редактирования.

Редактирование описания, приоритета, места и тегов через Telegram, отдельное редактирование Draft остаются за пределами этой реализации. Базовые действия над сохранёнными Task/Note готовы; этапы 10/13 оставлены частичными по расширенному перечню текущего ТЗ, включающему UX Draft.
## Команда /list

Отправьте `/list` или `/list@RoutineEscape_bot`, чтобы открыть текущую компактную сводку: сегодня и следующие два дня по вашему часовому поясу плюс свежие заметки/задачи без срока, максимум пять пунктов. Кнопка «Показать всё» ведёт в существующий полный список с пагинацией и карточками управления. Если записей нет, бот явно сообщает об этом; если записи есть только за пределами окна, предлагает открыть полный список.

Команда не создаёт Draft и показывает только записи отправителя в его личном чате. При открытом редактировании/подтверждении удаления `/list` не меняет выбранное поле или состояние; бот напоминает, что режим остаётся открытым и его можно отменить через `/cancel`. Команда добавлена в приветствие `/start`. Команды `/menu` и `/help` открывают меню и справку. Стандартное меню команд Telegram регистрируется при старте long polling.
## Уведомления и часовой пояс

Проверьте `/timezone`: бот покажет текущую зону, местное время и смещение. Например, `/timezone Asia/Qyzylorda` устанавливает UTC+05:00; `/timezone Europe/Moscow` — московскую зону. Существующие UTC-сроки не сдвигаются, меняются отображение и разбор новых дат. Зоны берутся из системной базы Windows/.NET; её актуальность влияет на смещения. Во время редактирования смена зоны просит сначала завершить или отменить ввод.

Для активного Reminder, незавершённой Task с явно заданным временем и Event бот отправляет уведомление в срок (проверка очереди каждые 5 секунд, плюс задержка сети). Если пользователь не подтвердил и не отложил, отправляется **один** повтор через 10 минут после успешной первой доставки. Дальнейшего автоматического повтора в этом цикле нет. «Готово» завершает задачу/напоминание; у события только подтверждает уведомление. «Отложить на 10 минут» и «На час» считают новый срок от нажатия, аннулируют старые кнопки/повтор и начинают новый цикл. У задачи/напоминания обновляется срок; у события откладывается только уведомление, исходное время события сохраняется.

Задачи с датой без явного времени не получают полуночное уведомление: подтверждение и карточка поясняют это. Назначьте время через карточку, чтобы включить доставку. Изменение времени, выполнение, отмена или удаление записи синхронизируют расписание в той же транзакции БД; изменение только текста не запускает цикл заново.

Миграция `NotificationSchedules` добавляет таблицу очереди и признак точного времени задачи без удаления записей. При первом включении она добавляет только будущие активные Reminder/Event. Исторические просроченные записи не рассылаются; существующие задачи не включаются автоматически, поскольку старые данные не различают дату и точное время. Для старой задачи укажите время заново в карточке. Миграция применена к локальной БД; количество существующих записей не изменилось.

Очередь переживает обычный перезапуск: пропущенная доставка с просрочкой до 24 часов отправляется при восстановлении, более старая приостанавливается без рассылки. Первая поздняя доставка запускает один повтор через 10 минут от фактической отправки. Ошибка Telegram оставляет тот же этап в очереди: задержки 30 секунд, 1, 2, 4, 8, затем до 15 минут; после 8 неудач доставка приостанавливается. Чтобы возобновить приостановленное расписание, задайте новое будущее время в карточке.

Работники используют PostgreSQL `FOR UPDATE SKIP LOCKED`; блокировка сохраняется до результата отправки и фиксации этапа. Это защищает от одновременных обычных отправок, но **не гарантирует exactly-once**: Telegram мог принять запрос до сетевого сбоя/отката транзакции, тогда retry может продублировать сообщение. Состояние редактирования остаётся рассчитанным на один локальный экземпляр, несмотря на защиту фоновой очереди от нескольких работников.

В дневном журнале ищите `Notification scheduler ready: database checked`, `NotificationId`, результат фактической отправки, retry/expired и действия кнопок. Тестовые уведомления в реальный чат не отправляются: sender подменяется, PostgreSQL-проверки выполняются в изолированной схеме. Миграция отдельно проверена на искусственных старых/будущих записях: в очередь попали только будущие Reminder/Event.
Число без месяца: «23го», «23-го», «23 го», «23 числа» (после «го» можно добавить «числа») относится к текущему месяцу в часовом поясе пользователя. Прошедшее время или невозможное число требуют уточнения, без переноса на следующий месяц. Можно указать месяц явно: «23 сентября в 13:00». Разбор действует при создании и редактировании даты; полный исходный текст сохраняется в названии, а «собес» остаётся Unknown с ручным выбором типа.

## Оформление и компактная навигация — 17 сентября 2026

При нажатии кнопки в личном чате бот сначала отправляет новый экран, затем удаляет сообщение бота, на котором нажата кнопка. При ошибке отправки старый экран сохраняется; если Telegram отказывает в удалении, новый ответ остаётся доступным. Ответы только всплывающей подсказкой ничего не удаляют. В актуальных списках, сводке, поиске и подтверждении сохранения название выделено жирным, дата — курсивом, просрочка — жирным с ⚠️. Каждая запись занимает две строки с отступом между записями. Пользовательские символы HTML экранируются; сохранённый текст и названия кнопок остаются исходными.
